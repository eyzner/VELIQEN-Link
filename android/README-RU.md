# VELIQEN Link для Android / VELIQEN OS

Готовый Android Studio проект — `kdeconnect-android/`. Основа: KDE Connect 1.37.3. Версия адаптации: 1.2.1. Полные исходники и лицензии включены.

## Новый главный экран

На главном экране находятся выбранный компьютер, состояние связи и четыре основных действия: **Экран**, **Файлы**, **Буфер** и **Звонки**. Настройки открываются кнопкой в верхней панели, доступы — отдельной строкой. Кнопка «Назад» возвращает из этих разделов на предыдущую страницу. В горизонтальной ориентации и на планшете блоки располагаются рядом, когда хватает места.

Базовый сценарий — открыть приложение, разрешить локальную сеть, выбрать найденный компьютер и подтвердить сопряжение. Разрешения объясняются по назначению: SMS, уведомления других приложений и управление экраном включаются для соответствующих возможностей. Уведомления самого Link помогают видеть входящие запросы; их отказ не помечает остальные выбранные функции как неготовые.

Исходные расширенные настройки KDE Connect доступны через **Настройки → Настройки возможностей**.

## Установка APK 1.2.1

Откройте `VELIQEN-Link-1.2.1-Android.apk` на телефоне и подтвердите установку. В полном комплекте файл находится в корневом `artifacts/`. При самостоятельной сборке Android-проект создаёт `android/artifacts/VELIQEN-Link-1.2.1-release.apk`; это то же приложение. Если Android попросит, разрешите установку приложений для того файлового менеджера или браузера, которым вы открыли APK. Режим разработчика и USB-отладка для обычной установки не нужны.

Это подписанный выпуск с постоянным приватным ключом VELIQEN. Приложение имеет собственный ID `tech.veliqen.link`, `versionCode` 13706 и не требует Google Play Services. Публичный сертификат и SHA-256 находятся в `RELEASE-SIGNING.json` и `signing/`. Приватный ключ не входит в исходники и публичные архивы.

### Переход с тестовых 1.0–1.2.0

Прежние тестовые APK использовали `org.kde.kdeconnect_tp` и общедоступный ключ разработки. Выпуск 1.2.1 устанавливается **как отдельное приложение**. Старые настройки и данные остаются в прежнем приложении. В новой версии один раз подтвердите сопряжение с Ubuntu и выдайте выбранные разрешения. Закройте или отключите старую версию после перехода, чтобы оба приложения не создавали одинаковые уведомления и подключения. Установщик ничего не удаляет автоматически.

Обновления публичного приложения `tech.veliqen.link` будут использовать этот же постоянный ключ. Они смогут сохранять его данные и сопряжения. Идентификатор приложения и подпись не следует менять после публикации.

### Обычный APK и системная сборка

Обычный APK работает в рамках разрешений Android. Фоновое чтение буфера в современных версиях Android недоступно: пользуйтесь кнопкой **Буфер** для отправки текста. Остальные доступы включайте по необходимости.

Для системной интеграции используйте `../rom/INSTALL-ROM.sh`. В Full/ROM-комплекте unsigned APK уже находится в `rom/payload/prebuilt/VELIQENLink.apk`. Source-архив не содержит собранных APK: выполните `bash android/BUILD-APK.sh --unsigned`, после чего интегратор найдёт APK в `android/artifacts/`. Сборка AOSP подписывает APK ключом `platform` вашей прошивки. Только соответствующая системная подпись или предусмотренная Android роль позволяет получить `READ_CLIPBOARD_IN_BACKGROUND`. Одного переноса APK в `priv-app` недостаточно. Пользовательский root не требуется.

Системная и обычная публичная сборки используют один ID, но разные подписи. Публичный APK не обновляет платформенную сборку. Для встроенного приложения выпускайте обновления вместе с ROM с сохранением её platform-ключа. Если в старом образе есть прежний `org.kde.kdeconnect_tp`, состав образа и миграцию нужно согласовать отдельно. Интегратор не удаляет старые приложения.

## Сборка в Ubuntu

Нужны JDK 21, Android SDK `platforms;android-37.0`, `build-tools;37.0.0`, platform-tools и доступ к Google Maven, Maven Central, JitPack и Gradle. Gradle Wrapper 9.6.0 входит в исходники.

Для обновлений **восстановите уже созданный ключ выпуска**. Положите `veliqen-link-release.p12` и `store-password` из личной резервной копии в `${XDG_DATA_HOME:-$HOME/.local/share}/veliqen-link/signing/`. Затем из каталога `android`:

```bash
export ANDROID_HOME="$HOME/Android/Sdk"
bash BUILD-APK.sh --release
python3 VERIFY-APK.py artifacts/VELIQEN-Link-1.2.1-release.apk
```

`--release` не создаёт новый ключ при его отсутствии. Для первоначальной сборки отдельного нового проекта есть явная команда `bash INIT-SIGNING.sh`. Она отказывается заменять существующие ключ или пароль. Новый ключ не годится для обновления опубликованного VELIQEN Link.

Для CI можно задать `VELIQEN_KEYSTORE`, `VELIQEN_STORE_PASSWORD`, `VELIQEN_KEY_ALIAS` и `VELIQEN_KEY_PASSWORD`. Храните значения в Secrets, а не в репозитории. Альтернативный каталог ключа задаётся через `VELIQEN_SIGNING_DIR`. Пароли не передаются в аргументах команд и не печатаются. Скрипт не меняет системную Java или SDK.

`--unsigned` создаёт APK для ROM. `--development` создаёт отдельное тестовое приложение `tech.veliqen.link.development` с публичным debug-ключом. Его нельзя публиковать как официальный выпуск. Параметр `--personal` оставлен как синоним `--release`. Для сборки с уже заполненным кэшем Gradle можно добавить `--offline`.

В Android Studio откройте `kdeconnect-android`, выберите JDK 21 и вариант `veliqen`. Namespace исходников KDE остаётся `org.kde.kdeconnect_tp`; он не определяет ID установленного приложения. Вариант по умолчанию unsigned, либо использует явно заданные `VELIQEN_*` переменные подписи.

## Подключение

Откройте приложение, разрешите локальную сеть и сопрягите телефон с вашим Ubuntu-компьютером, проверив имя устройства и запрос на обоих концах. Включайте доступы к SMS, контактам, уведомлениям и файлам только для нужных вам функций. Отдельная настройка Bluetooth нужна для сотовых звонков через ноутбук; показ экрана и файлы используют Wi-Fi.

## Экран без отладки USB

Начиная с версии 1.1 обычный показ экрана использует MediaProjection Android. Режим разработчика, ADB, ввод IP и кода сопряжения для него не нужны.

Откройте **Экран** на Ubuntu и отправьте запрос, затем откройте уведомление на телефоне. Либо нажмите **Экран** с подписью **Показать на Ubuntu** прямо в приложении телефона. Подтвердите стандартный запрос Android — изображение откроется на компьютере.

Для управления отметьте **Разрешить управление в этом сеансе** перед запуском и включите отдельную службу **VELIQEN: управление экраном** в специальных возможностях. Только просмотр работает без этого разрешения. При блокировке телефона, завершении показа или потере соединения сеанс прекращается. Пароль и PIN не снимаются; защищённые экраны могут скрываться системой. Текст в поле пароля через удалённый ввод не записывается.

Оба устройства используют сертификаты уже подтверждённого сопряжения. Новый канал проверяет сертификат каждого конца и не принимает команды от неизвестного устройства. Кадры не записываются в файл. Для подключения используйте Ubuntu-часть из этого комплекта 1.2.1; нативный протокол появился в версии 1.1.

Android запрашивает согласие на каждый новый сеанс показа. Сотовый звук по Wi-Fi не передаётся: для звонков используется Bluetooth HFP. scrcpy сохранён на Ubuntu как отдельный дополнительный способ для уже авторизованного ADB.

Подробности — `../docs/NATIVE_SCREEN_RU.md`.
